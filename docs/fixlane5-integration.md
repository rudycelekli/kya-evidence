## Existing requirement text affected

- KYA-REL-004 says the readiness report "MUST exit 1 and MUST NOT print the ready line when any automated gate fails". It stays true. Its traced test "exit code is 1 and no ready line when an automated gate fails" now asserts the `OBSERVATIONS INJECTED` verdict instead of `NOT READY` for a file input, because file input is never ready. Its traced test "exit code is 0 with the ready line when every automated gate passes" now injects the collector (a simulated real run) instead of a file.
- KYA-REL-003 "MUST NOT create a provenance attestation on a dry run" stays true; the attestation moved to the `attest` job. The traced test titles are unchanged.
- The release-workflow test "the build job runs the gates and builds verifies and attests the tarball" was retitled "the build job runs the gates and builds verifies and uploads the tarball without attesting" (not traced in `requirements.json`).
