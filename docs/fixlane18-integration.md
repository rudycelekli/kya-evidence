# Fix lane 18: redundant killers for single-test mutation controls

## What changed

The mutation harness (`scripts/mutation-check.mjs`, 87 controls) reported `allKilled: true` on main, but 49 controls were killed by exactly one test. A control caught by one test has no redundancy: weakening or deleting that one test would silently stop guarding the gate.

This lane adds one independent second test for each of those 49 controls, in seven new files named `test/mutation-redundancy-*.test.mjs`. The second tests use a different input, a different entry point or a different observable than the existing killer. Where the first killer calls the library, the second mostly goes through a public command line tool (`kya-check`, `kya-campaign`, `kya-bridge`, `privacy-scan`, `conformance-report`) or through another exporter or validator. The ledger tests forge correctly signed entries with the issuer key and judge them through `kya-campaign verify-ledger`, so the replay rules are tested and not only the signature.

No mutant was changed. No file under `src/conformance/` was touched. The only edit to `scripts/mutation-check.mjs` adds the seven new test files to the list of files that each mutant run executes, so the new tests count when the harness decides whether a mutant is killed.

## Result

| | Before | After |
| :--- | :--- | :--- |
| Controls | 87 | 87 |
| Controls killed by exactly one test | 49 | 0 |
| `allKilled` | true | true |

The per-control `killedBy` lists are in the JSON that the harness prints. The baseline test count in the harness grew from 405 to 464.

## Controls where the second killer shares the entry point

Two controls could not get a second killer through a different entry point. Each still has a second test with a different input.

- Capture-issuer evidence-signer check (`src/campaign/domain/roles.mjs`): `evidenceKeyIds` is a parameter that no shipped caller passes. Only a direct call reaches it. The second test uses two issuer anchors, puts the clashing key on the second anchor, and checks the evaluator-key branch separately.
- Report exit-code check (`src/conformance-report/report.mjs`): a real test file that exits non-zero after passing tests still produces a failing top-level TAP entry, so the process-outcome clause is reachable only with a process record that has no failing TAP line, which the command line tool cannot produce without a timeout. The second test calls `mapTapToRequirements` with parsed TAP output and four process outcomes (kill signal, null exit, error code, buffer error) across two files.

## What is not verified

- The harness is textual, targeted mutation of 87 anchored fragments. It is not exhaustive verification and a second killer for a control says nothing about gates that have no control.
- A second killer was shown to fail under its own mutant. It was not shown to catch every other way that gate can break.
- The boundary tests (expiry, start, cooling off) use millisecond values different from the first killers, but they exercise the same comparison, so they are redundancy against deletion of the first test, not an independent oracle for the comparison.
- The privacy scan tests check that chosen sample values are not echoed. They do not show that no other value can leak.
- Linux and Windows were not run.
