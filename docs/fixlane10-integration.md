# Fix lane 10: score card CLI wiring and second verifier, integration note

Status: proposal for the integrator. `evidence/requirements.json` is not edited by this lane. See [ADR-0033](adr/0033-kya-score-benchmark-profile.md) (Proposed) and [fix lane 8](fixlane8-integration.md).

Review boundary: the second verifier (`interop/score-verifier/verify_score_card.py`) was written by the same team in the same session family as the first. It shows that the ADR text is sufficient to recompute a card, and it found real gaps in that text. It is not independent review, not a statistician review and not an outside implementation.

## What changed

- `kya score build|verify` delegates to `scripts/kya-score.mjs` through the existing delegation table in `bin/kya.mjs`. Help text lists it. No existing command changed.
- `package.json` exports `./kya-score`; typings are in `src/kya-score/index.d.ts` and re-exported as types only from `src/index.d.ts`. The root runtime exports (`src/index.mjs`) are unchanged. The typings were not compiled by `tsc` (no TypeScript is installed in this repository).
- `interop/score-verifier/verify_score_card.py`: Python 3 standard library only, run with `python3 -I`.
- `interop/score-verifier/vectors.json` (56 vectors, generated by `scripts/score-vectors.mjs`, `--check` mode available): valid cards, each tamper class of `test/kya-score.test.mjs` including re-sealed and digest-recomputed edits, operator-statement edits, and malformed input. Expected validity is stated by intent in the generator.
- ADR-0033 gained a normative layout and algorithm section and a corrected item 8.
- `docs/BENCHMARKS.md` gained a reviewer section on reproducing a card; `README.md` links it.

## Disagreement log

Method. The first Python draft was written from the ADR summary text only, plus the field names of one generated sample card (the ADR did not list them). It was then run on the shared vector set. It disagreed with the JavaScript verifier or with the stated intent on 18 of the 53 vectors that existed then: 14 valid cards rejected by Python, and 4 others. The JavaScript source was read only after that. Each item below was resolved by writing the missing rule into the ADR, not by changing the JavaScript verifier, except D11 where the ADR claim was wrong and the code was right.

| # | Where the text was silent or wrong | Draft behaviour | JavaScript behaviour | Resolution |
| :-- | :--- | :--- | :--- | :--- |
| D1 | Card members and item fields were not listed anywhere in the ADR. A verifier cannot be written from the ADR alone | learned from a generated sample card | exact member sets | Layout section added to the ADR |
| D2 | Seed derivation said only "sfc32 keyed by SHA-256 of the seed string" | SHA-256 of the seed bytes | SHA-256 of `kya.score.seed/v1`, a line feed, then the seed | Stated in the ADR |
| D3 | Warm-up not mentioned | none | 12 outputs discarded | Stated in the ADR |
| D4 | Step order not mentioned | published sfc32 (old `d` added, then incremented) | `d` incremented before it is added to the output, not the published algorithm | Stated in the ADR with the explicit difference from published sfc32 |
| D5 | One seed for three aggregates assumed | same seed for headline, held-out and public | seed plus a vertical bar plus `all`, `heldout`, `public` | Stated in the ADR. The draft agreed on the 30 item sample only because the held-out and public score grids are coarse |
| D6 | Rounding of mean, sd, share, cost and runtime unspecified | 2 and 6 decimals, floats | 6 decimals for variance, whole micro-USD for cost, 3 decimals for runtime, with `Math.round` halves up | Stated in the ADR |
| D7 | Item order and a missing `canaryExposed` | did not normalise | items sorted by id in UTF-16 order, flag always present, whole-card equality | Stated in the ADR (`tamper-item-order-resealed`, `tamper-missing-canary-flag-resealed`) |
| D8 | Judge shape: the ADR said "identity and digest" | `id`, `version`, `digest` | `id`, `digest` | Stated in the ADR |
| D9 | A set whose items are all held out | crashed on an empty public part | `public` is `null` and `publicMinusHeldOut` is `null` | Stated in the ADR (`valid-all-items-held-out`) |
| D10 | Canonical number text: SPECIFICATION says only "bounded sorted-key JSON subset". The existing Python canonicalizer refuses most doubles | not reusable | ECMAScript number text | Stated in the ADR; the verifier carries its own number formatter |
| D11 | ADR item 8 said that editing any manifest field fails even after re-seal | n/a | accepts a re-sealed edit of a field no computation reads (subject version, judge, offline flag, evaluator digest, holdout commitment value) | Spec bug. The ADR text was wrong, since such an edit is indistinguishable from an honest build. Text corrected, five `operator-statement` vectors added, both verifiers accept them. Only a signature would bind these fields |

Also caught by the cross-check but not a specification gap: my own `tamper-variance-resealed` vector edited `sd` to the value it already had, so it was a no-op. It now sets `sd` to 1.

After the ADR section was added and the verifier was rewritten to follow it, all 56 vectors agree (stated expectation, JavaScript, Python, and for valid cards the same score and card digest). A scratch fuzz of 120 random valid cards (random sizes, repeats, outcomes, fractional costs and durations including `1e-7` and `1e9`, a non-BMP seed) also agreed; it is not committed.

## What is not verified

- The Python verifier is by the same team. The rewrite followed an ADR section written after seeing the first disagreements, so it shows the section is sufficient and consistent with the code on these inputs. It does not show the profile is the right design.
- Agreement on 56 vectors and one scratch fuzz is evidence about those inputs only. Hidden disagreement may remain, for example in number formatting outside the ranges exercised, or in JSON file parsing: the Python verifier rejects duplicate members and non-finite numbers itself, while the JavaScript CLI relies on the repository `parseJson`. No vector covers duplicate members at the file level.
- One host (macOS, Node 22.19, Python 3.13). Cross-platform float agreement is not tested. A host without `python3` skips the Python half with a flagged skip message; that run did not execute the second verifier.
- The typings were not compiled.
- Nothing here changes the earlier boundary: no real subject, no lab, no statistician review, no predictive validity, no inter-assessor agreement.
